# 阶段 0 运行说明

## 1. Maven 与测试

在仓库根目录执行：

```bash
mvn -U install
```

首次运行会拉取 Testcontainers 使用的 MySQL、Redis、RabbitMQ 和 MongoDB 镜像。MySQL 初始化在较慢的 Docker 磁盘上可能超过一分钟，测试已配置三分钟启动窗口。

## 2. 配置边界

本地 Docker Compose 中的 `nacos`、`yuanlive` 等账号仅用于开发环境。部署到共享测试、预发和生产环境时，必须通过部署平台注入实际值，不得将真实密码、Token、邮件授权码、模型 API Key 或 MinIO 密钥提交到仓库。

需要由环境变量或部署平台提供的敏感配置包括：

| 变量 | 用途 |
| --- | --- |
| `YUANLIVE_MAIL_USER` | 邮件发件账号 |
| `YUANLIVE_MAIL_PASSWORD` | 邮件授权码 |
| `NVIDIA_API_KEY` | AI 模型访问密钥 |
| `EMBEDDED_KEY` | 向量模型访问密钥 |
| `AMAP_API_KEY` | 地图服务密钥 |
| MinIO access key / secret key | 对象存储访问凭据 |

Nacos 负责非敏感的服务发现、Redis、RabbitMQ 和业务开关配置。密钥必须使用部署平台密文或 Nacos 加密能力，并按环境隔离命名空间；开发配置不可直接提升到生产环境。

## 3. 消息失败处理

AI 风控送审队列使用 `reliableRabbitListenerContainerFactory`：初始消费失败后按 1 秒、2 秒、4 秒退避重试，仍失败则进入 `live.analysis.dlx` 的 `live.analysis.dead.queue`。风控工作流完成前不会确认消息；人工审核节点仅保留检查点，不会自动批准。

钱包、礼物和收益事件从阶段 1 起必须额外实现 Outbox、业务 `eventId` 幂等记录和死信重放审计，详见 `消息可靠性规范.md`。
