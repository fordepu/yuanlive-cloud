# WebSocket 连接与房间路由 PRD

## 1. 产品目标

将客户端的实时连接从“登录后全局连接同时承担房间消息”的单一模型，调整为应用级连接与房间级连接分离的模型。用户进入应用后即可接收全局实时通知；每打开一个直播观看页或主播弹幕页，再建立一个只服务于该直播间的连接。

在 `yuanlive-live-service` 多实例部署、扩缩容和实例故障期间，系统必须只将私信或房间事件投递到实际承载目标连接的实例，不能让每个实例都消费并判断一遍。

## 2. 用户场景

| 用户 | 场景 | 期望结果 |
| --- | --- | --- |
| 已登录用户 | 进入首页、钱包、个人中心 | 主页面保持一条应用级连接，能接收异地登录、系统通知和个人实时提醒。 |
| 观众 | 打开一个直播间 | 该直播页创建一条房间级连接，只接收该房间聊天、礼物、点赞和房间通知。 |
| 观众 | 同时打开两个直播间 | 每个观看页各有独立连接，两个房间互不覆盖、互不串消息。 |
| 主播 | 开播并打开弹幕窗口 | 弹幕窗口创建主播房间专属连接，实时显示本房间聊天与礼物。 |
| 平台 | 扩容、缩容或实例故障 | 已连接用户不因路由目录短暂变化而系统性漏收；重连后可恢复房间消息。 |

## 3. 范围

### 3.1 包含

- 应用级和房间级 WebSocket 连接的客户端生命周期管理。
- 房间级握手携带 `roomId`，并在服务端校验后绑定一个房间。
- `USER_MAP` 仅保存应用级主连接；`ROOM_MAP` 保存本机房间连接组。
- Redis 维护用户主连接归属及房间承载实例集合，并使用 TTL 与心跳续期。
- RabbitMQ 实例专属队列，实现私信单播与房间事件定向多播。
- 事件 `eventId` 去重、顺序号 `seq`、断线重连后的消息补拉。
- 扩缩容、实例下线和连接迁移时的路由目录清理与恢复。

### 3.2 不包含

- 将一个 WebSocket Channel 订阅多个直播间。
- 使用房间连接处理钱包扣款、充值或其他资金事实。
- 建设完整的聊天历史产品；本阶段只定义用于断线补偿的有界消息缓冲。
- 通过全实例 fanout 广播普通聊天消息。

## 4. 连接模型

```text
登录成功
  └─ 应用级 WebSocket（scope=APP，不加入直播间）
       └─ USER_MAP[userId] = 主页面 Channel

打开直播间 room-A
  └─ 房间级 WebSocket（scope=ROOM，roomId=room-A）
       └─ ROOM_MAP[room-A] = 本机 ChannelGroup

打开直播间 room-B
  └─ 房间级 WebSocket（scope=ROOM，roomId=room-B）
       └─ ROOM_MAP[room-B] = 本机 ChannelGroup
```

每个房间级连接只允许一个 `roomId`。客户端关闭观看页时发送 `LEAVE_ROOM` 并关闭该连接；异常断开由服务端连接关闭回调清理。

灰度期间，未携带 `scope` 的旧客户端连接标记为 `LEGACY`，保留其首帧 `JOIN_ROOM` 和切房行为，防止已发布客户端被升级中断。`LEGACY` 不是对外新协议，待新客户端 APP/ROOM 双连接完成全量发布后移除。

### 4.1 新连接接入路由

一致性哈希只用于选择“新建连接最初接入哪个实例”，不用于判断已建立连接的实际位置：

| 连接类型 | 网关路由键 | 路由键来源 | 目的 |
| --- | --- | --- | --- |
| APP | `userId` | 网关验证 Token 后提取的用户标识 | 让同一用户的主页面重连尽量稳定落到同一实例。 |
| ROOM | `roomId` | 已校验的握手查询参数 | 让同一房间的连接尽量集中到同一实例，优先本机广播。 |

客户端提交的 `userId` 不得作为路由依据。网关未能验证 Token 或提取身份时，必须拒绝 APP WebSocket 握手，不能退化为相信查询参数。

网关使用 Rendezvous Hash（最高随机权重哈希）实现上述一致性哈希：对路由键和每个健康候选实例计算稳定分数，选择最高分实例。该计算只在新 WebSocket 握手接入时执行，不会新增任何 WebSocket 握手或网络请求；实例数量处于常规服务规模时，遍历候选实例的本地计算成本可忽略。

## 5. 消息投递规则

### 5.1 应用级私信与通知

已建立 APP 连接的消息投递以 Redis 的 `userId → instanceId:connectionId` 记录为准，而不是重新计算 `hash(userId)`。发送方可使用 3 至 10 秒的本地路由缓存减少 Redis 读取；缓存缺失、过期、目标实例 epoch 不匹配、目标 Channel 不存在或实例租约失效时，必须删除缓存、查询 Redis 并以同一 `eventId` 向当前目标实例重投。

目标实例从本机 `USER_MAP` 取出与 `connectionId` 匹配的 Channel 后写入消息。用户不在线时按消息类型进入离线消息、丢弃或业务重试，不能改为广播给所有实例。

### 5.2 房间聊天与实时事件

正常情况下，网关按 `roomId` 一致性哈希，令同一房间连接集中到一个实例；用户聊天到达 owner 实例后，直接向本机 `ROOM_MAP[roomId]` 广播。

发生扩缩容、故障恢复或旧连接尚未迁移完成时，Redis 中一个房间可能对应多个承载实例。发送方查询实例集合，并仅向集合中的实例专属队列定向多播；每个实例只向自身的 `ChannelGroup(roomId)` 写入。房间集合的本地缓存同样只作短 TTL 优化；高可靠事件或缓存失效时必须直接查询 Redis，不能因缓存缺少新实例而漏发。

```text
CHAT(room-A, eventId)
  → Redis: ws:room:room-A:instances = {instance-2, instance-4}
  → instance-2 专属队列 ─┐
  → instance-4 专属队列 ─┴→ 各自本机 ROOM_MAP[room-A] 广播
```

## 6. 验收标准

- 登录后只创建一条 `scope=APP` 连接；普通页面切换不增加连接。
- 每个直播观看页和主播弹幕窗口创建一条独立 `scope=ROOM` 连接。
- 同一用户同时打开多个房间时，消息只出现在对应房间页面。
- 房间连接不得覆盖 `USER_MAP[userId]` 中的应用级主连接。
- 私信只投递给用户主连接所在实例；房间消息只投递给 Redis 路由目录中的承载实例。
- 对普通聊天，任何无目标房间连接的实例都不消费该房间消息。
- 扩缩容期间同一房间分布到多实例时，所有仍在线连接最多收到一次消息。
- 连接断开并重连后，客户端基于 `seq` 补拉缺失消息；重复 `eventId` 不重复展示。
- Redis 路由记录在连接、关闭和实例下线后能正确过期或移除，不出现永久脏路由。
- APP 连接在新建时按认证 `userId` 哈希接入，ROOM 连接在新建时按 `roomId` 哈希接入；消息投递不以重新计算的哈希结果替代 Redis 路由目录。

## 7. 发布与回滚

发布顺序：先发布服务端连接范围、路由目录和实例专属队列能力；再发布客户端房间级连接；最后启用网关按 `roomId` 路由。灰度阶段保留旧 `JOIN_ROOM` 协议兼容，但服务端需拒绝“握手房间与 JOIN_ROOM 房间不一致”。

回滚时关闭网关房间路由和新客户端特性开关，服务端继续接受旧连接；不要删除 Redis 路由键、队列或补偿缓冲，待所有旧连接自然断开后再清理。
