# 阶段 1 前端适配实施计划

> **供执行智能体使用：** 按任务逐项实施并在每个任务完成后执行对应测试；任务使用复选框跟踪。

**目标：** 同时完成 `yuanlive-tauri` 客户端和 `yuanlive-admin` 管理端对阶段 1 钱包送礼资金闭环的前端适配。

**架构：** 后端钱包服务提供资金事实和只读查询；客户端通过 HTTP 创建充值/送礼订单，通过 WebSocket 接收礼物展示；管理端只读查询订单和对账报告。两个前端项目分别保持现有请求封装、Pinia/路由和测试习惯，不共享运行时代码。

**技术栈：** Vue 3、TypeScript、Pinia、Naive UI、Tauri Rust WebSocket、管理端 Element Plus、Vitest、Playwright。

**依据：** [PRD](../prd/2026-08-26-阶段1前端适配-prd.md)、[SPEC](../specs/2026-08-26-阶段1前端适配-spec.md)、[阶段1送礼资金闭环 SPEC](../specs/2026-08-25-阶段1送礼资金闭环-spec.md)。

## 全局约束

- 只能在各前端项目的 `dev` 分支开发；开始修改前确认分支和工作区状态。
- 金币按整数处理；前端不使用浮点数计算资金结果。
- 客户端不提交价格、主播、抽成、收益或图标作为资金参数。
- 送礼请求必须使用 UUID `requestId`，重试复用原值。
- 礼物展示按 `eventId` 去重；展示失败不修改资金事实。
- 管理端财务页面只读，不提供补账、改余额和死信重放。
- 所有新增复杂幂等、重试和消息边界逻辑补充简体中文注释。
